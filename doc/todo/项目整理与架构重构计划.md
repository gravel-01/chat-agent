# 高情商聊天回复助手 项目整理计划

> 状态更新（2026-04-12）
>
> - 项目已收敛为纯桌面端
> - `apps/web/` 已删除
> - 当前唯一产品主线是 `apps/desktop/`
> - 根目录 `chat_assistant.py` 仅保留为兼容启动入口

## 1. 当前目标

当前不再考虑 Web 端。

后续整理只围绕桌面端做三件事：

1. 让本地桌面版稳定可运行
2. 把大文件里的业务能力拆出来
3. 让后续加功能更容易维护

## 2. 当前真实问题

### 2.1 控制器文件曾出现残缺

当前仓库的主要问题不是环境，而是代码在重构过程中出现过残缺状态。

例如：

- `apps/desktop/controller.py` 缺少核心方法
- 信号已绑定，但实现不完整
- 导致即使在正确环境里运行，也会直接启动失败

### 2.2 业务和桌面 UI 仍然耦合

当前 `apps/desktop/core.py` 仍然同时承担：

- 配置读取
- 文档解析
- OCR 调用
- Prompt 组装
- 文心接口调用
- 后台线程处理

这会继续抬高维护成本。

### 2.3 启动方式和文档容易分叉

后续要始终保证：

- 文档里的启动命令
- 本地实际启动入口
- 依赖文件

三者保持一致。

## 3. 当前目录目标

```text
高情商聊天回复助手/
├─ apps/
│  └─ desktop/            # 唯一桌面端主线
├─ chat_assistant.py      # 兼容启动入口
├─ doc/
├─ skill-data/
├─ .env.example
└─ requirements.txt
```

## 4. 后续整理顺序

### Phase 1：先保证桌面端稳定运行

目标：

- `python -m apps.desktop.main` 可以稳定启动
- 控制器、截图、文档载入、结果展示链路完整

### Phase 2：拆 `core.py`

优先拆出：

1. `config`
2. `document`
3. `ocr`
4. `prompt`
5. `llm`

### Phase 3：收敛桌面壳层职责

桌面端目录后续应只保留：

- UI 组件
- 控制器
- 热键与 Qt 适配
- 后台线程壳层

### Phase 4：补齐工程化

后续补：

- `requirements.txt`
- 启动文档
- 基础测试
- 错误日志

## 5. 当前约束

在下一轮整理前，先遵守下面几条：

1. 不再引入 Web 相关文件
2. 不再把新功能继续堆进 `apps/desktop/core.py`
3. 新功能优先按桌面端调用 + 业务能力拆分的方式落地

## 6. 结论

当前项目已经明确为纯桌面项目。

后续所有整理动作，目标都应服务于一句话：

让本地桌面版稳定可跑，并且越来越容易维护。
