# 高情商聊天回复助手 贴边浮窗版 PRD

## 1. Summary

这份文档定义一版新的桌面端小应用形态：把当前“必须先按全局热键”的工具，改成一个常驻桌面边缘的贴边浮窗助手。用户只需要点击浮窗上的 `截图` 按钮，框选聊天内容，系统就自动完成 OCR、调用文心大模型，并在侧边结果面板里给出几条可直接复制的回复建议。

这次改版的核心不是把旧流程搬进一个大面板，而是把产品改成“鼠标优先、一步直达、失败可恢复”的形态。热键不再是主入口，只保留为可选能力。

## 3. Background

当前版本已经跑通主链路：

1. 用户按全局热键。
2. 程序弹出截图遮罩。
3. 程序执行 OCR。
4. 程序调用文心生成回复。
5. 程序弹出结果浮窗。

这个版本证明了功能有价值，但产品结构有一个根问题：入口被绑死在热键上。

从当前实现看，热键失败不是“小问题”，而是“前置致命失败”：

- 热键注册失败时，程序直接弹错误框并退出。
- 用户平时看不到入口，只能记住组合键。
- 企业微信、微信、输入法、录屏工具、截图工具都可能占用热键。
- 结果只在最后出现，中间过程没有稳定的操作中心。
- 如果 OCR 不准或模型超时，用户只能重新来一遍，恢复成本高。

为什么现在要改：

- 这个工具已经不是一次性的脚本，而是高频桌面工作流。
- 用户真正需要的是“聊天窗口旁边一直有一个能点的按钮”，而不是“记住一个不一定能用的热键”。
- 现有 PyQt 架构已经具备截图遮罩、异步线程、浮动窗口的基础，适合继续演进成稳定的小应用。

## 4. Objective

### 4.1 目标

把产品升级成“贴边浮窗助手”。默认主流程只需要：

1. 点击浮窗上的 `截图`
2. 框选聊天内容
3. 看到几条可直接复制的回复

用户不需要先设置热键，不需要先展开大面板，也不需要先选一堆风格参数。

### 4.2 为什么重要

- 对用户：入口更稳定，更容易找到，也更符合“看见消息就点一下”的习惯。
- 对产品：从“热键工具”升级成“桌边助手”，更适合日常长时间使用。
- 对开发：把产品骨架理顺后，后续再加历史、模板、二次改写会更自然。

### 4.3 成功指标

#### O1：让主流程彻底摆脱热键依赖

- KR1：V1 中，核心流程默认可完全通过鼠标点击完成。
- KR2：热键关闭或注册失败时，应用仍可正常启动并提供完整能力。
- KR3：首次使用用户在 5 秒内能知道“点哪里开始截图”。

#### O2：让用户一轮操作就拿到可发结果

- KR1：从点击 `截图` 到看到回复建议，用户操作不超过 2 个动作。
- KR2：结果出现后，复制任意一条回复只需要 1 次点击。
- KR3：默认流程里不要求用户先编辑 OCR 文本或先选风格。

#### O3：让失败后的恢复足够轻

- KR1：OCR 失败时，用户可直接 `重新截图`、`贴图` 或 `手动输入文字`。
- KR2：模型超时或报错时，已识别文字必须保留，用户可以 `重试生成`。
- KR3：关闭结果面板后，最近一次截图文本和回复仍能从浮窗重新打开。

## 5. Market Segment(s)

### 主要用户

- 高频聊天用户：看到消息后，希望马上得到几条能直接发的回复。
- 职场沟通用户：在微信、企业微信、钉钉等场景里，需要更稳妥、更得体的措辞。
- 客服、运营、内容人员：需要短时间内连续处理多段对话，不希望每次都重新组织语言。

### 用户任务

- 当我收到一段聊天内容时，我想点一下就得到几条回复，而不是先折腾工具。
- 当 OCR 识别不准时，我想补一补文字，而不是整轮重来。
- 当热键冲突时，我不想排查冲突，我只想继续工作。

### 使用约束

- 应用必须尽量轻，不要长时间遮挡聊天窗口。
- 浮窗可以置顶，但不能频繁抢输入焦点。
- 用户可以接受 1 到 5 秒的等待，但要看到明确状态。
- 很多办公电脑会限制键盘监听或全局快捷键，所以主入口不能依赖热键。

## 6. Value Proposition(s)

这个产品解决的不是“写一句高情商回复”这么窄的问题，而是“在聊天软件旁边，用最少动作拿到几条能直接发的回复”。

### 用户得到的价值

- 入口可见：桌边一直有一个可点的 `截图` 浮窗。
- 路径更短：截图后自动识别、自动生成，不需要手动串流程。
- 结果更近：回复直接出现在浮窗侧板里，不需要再找弹窗。
- 恢复更轻：失败后保留上下文，随时能重试、改字、换一版。

### 用户避开的痛点

- 忘记热键。
- 热键被其他软件占用。
- 程序已经运行，但不知道如何开始。
- OCR 识别错了，却没有轻量修正入口。
- 生成失败后，前面做过的操作全部白做。

### 相对当前版本的优势

- 从“热键触发工具”升级成“贴边助手”。
- 从“串行脚本”升级成“有稳定入口和状态的桌面产品”。
- 从“最后才出现结果”升级成“从采集到结果都围绕一个固定面板完成”。
- 从“出错就卡住”升级成“每一步都有下一个可选动作”。

## 7. Solution

### 7.1 UX / Prototypes

新版产品采用“三层结构”，而不是常驻一个大工作台。

#### 层 1：贴边浮窗把手

- 默认吸附在屏幕右侧中部，也允许拖到左侧。
- 默认宽度约 60 到 72 像素，高度约 140 到 180 像素。
- 默认只显示 1 个主动作按钮：`截图`。
- 次级入口为 `贴图` 和 `打开上次结果`，只在悬停或轻展开时显示。
- 使用状态点表达当前状态：
  - 绿色：就绪
  - 蓝色：识别/生成中
  - 橙色：最近一次出错

建议线框：

```text
+-----------+
|   ● Ready |
|           |
|  [截图]   |
|           |
| [贴图][↗] |
+-----------+
```

这个把手的目标是：

- 始终看得见
- 占位很小
- 主动作足够明确
- 不需要用户记任何快捷键

#### 层 2：结果侧板

- 用户完成截图后自动从浮窗侧边展开。
- 默认宽度 360 到 400 像素。
- 默认高度 460 到 560 像素。
- 展开后优先显示进度，再显示结果，不要求用户先做设置。

建议线框：

```text
+--------------------------------------+
| 高情商助手                 收起   ×  |
| 正在生成回复... / 已生成 3 条建议     |
|--------------------------------------|
| 识别文字（折叠摘要）         [改文字] |
| 对方说今天方案还没看到，你那边...      |
|--------------------------------------|
| 推荐回复                               |
| 【稳妥版】              [复制] [重写] |
| 好的，我这边马上整理好发你，稍等我几分钟。|
|                                      |
| 【自然版】              [复制] [重写] |
| 收到，我现在补一下，马上给你。        |
|                                      |
| 【加分版】              [复制] [重写] |
| 抱歉让你久等了，我这边已经在处理，稍后第一时间发你。|
|--------------------------------------|
| [再来三条] [更礼貌] [更简短] [重新截图] |
+--------------------------------------+
```

这层是产品的真正工作中心。用户大多数时候只会停留在这里：

- 看识别结果摘要
- 复制某一条回复
- 点一次重写或快速改风格

#### 层 3：截图遮罩

- 只有用户点 `截图` 时才出现。
- 自动隐藏贴边浮窗，避免把自己截进去。
- 支持拖框、按 `Esc` 取消。
- 完成截图后立即进入 OCR 和生成流程。
- 至少支持“鼠标当前所在屏幕”的正确截图；多显示器完整支持作为明确要求。

#### 补充层：编辑抽屉

编辑抽屉不是默认主界面，而是结果侧板中的一个二级区域，只在需要时展开。

- 用户点 `改文字` 时展开。
- 内容包括：
  - OCR 文本编辑框
  - 场景模板切换
  - `重新生成`
- 这样用户只有在 OCR 不准或想微调时才进入高级区。

建议线框：

```text
+--------------------------------------+
| 改文字 / 换风格                        |
|--------------------------------------|
| [可编辑 OCR 文本框..................] |
|                                      |
| 场景模板                              |
| [默认] [职场] [安慰] [拒绝] [邀约]    |
|                                      |
| [取消] [保存并重新生成]               |
+--------------------------------------+
```

#### 核心交互原则

- 主流程必须“一键开始”，不能先逼用户做配置。
- 风格和编辑属于增强能力，不属于主入口流程。
- 结果面板必须记住最近一次内容，关闭后可重新打开。
- 所有错误都要告诉用户下一步能做什么。
- 浮窗应尽量少抢焦点，复制完成后优先把注意力还给聊天软件。

#### 主流程

1. 用户点击贴边浮窗上的 `截图`。
2. 系统打开截图遮罩，用户框选聊天区域。
3. 系统自动执行 OCR。
4. OCR 成功后，系统自动调用文心生成 3 条默认回复。
5. 结果侧板自动展开，展示回复卡片。
6. 用户点击任意一条 `复制`，然后回到聊天软件粘贴。

#### 二级优化流程

1. 用户在结果侧板点击 `改文字`。
2. 展开编辑抽屉，修改 OCR 文本或切换场景模板。
3. 点击 `保存并重新生成`。
4. 系统保留原截图，重新生成新的回复组。

#### 异常流程

- 热键不可用：
  - 应用照常启动。
  - 设置页显示 `热键未启用` 或 `热键冲突`。
  - 不弹阻断式错误框，不退出程序。

- OCR 没识别出文字：
  - 结果侧板显示 `没有识别到可用文字`。
  - 提供 `重新截图`、`贴图`、`手动输入文字` 三个动作。

- 模型超时或失败：
  - 保留 OCR 文本。
  - 显示 `重试生成` 和 `改文字后再试`。

- 剪贴板里没有图片：
  - 提示 `剪贴板里没有图片，请先截图或复制图片`。

### 7.2 Key Features

#### 功能 1：贴边浮窗把手

- 始终可见，始终能点。
- 支持左/右吸附、拖动、位置记忆。
- 保持轻量，不默认展开成大工作台。

#### 功能 2：一键截图直出回复

- 点击 `截图` 后，系统自动串联截图、OCR、生成。
- 默认不需要用户再点一次 `识别` 或 `生成`。
- 这是 V1 最重要的路径。

#### 功能 3：结果侧板

- 自动展示 3 条回复建议。
- 每条卡片提供：
  - `复制`
  - `重写`
- 面板底部提供：
  - `再来三条`
  - `更礼貌`
  - `更简短`
  - `重新截图`

#### 功能 4：OCR 文字修正

- 识别文字以“摘要 + 编辑抽屉”的方式存在。
- 默认折叠，避免界面太重。
- 需要时可展开编辑并重新生成。

#### 功能 5：多入口补救

- `截图`：主入口。
- `贴图`：从剪贴板导入截图。
- `手动输入文字`：OCR 失败时的最后兜底。
- 托盘菜单里的 `开始截图`：当浮窗被收起或遮住时使用。

#### 功能 6：可选热键，而不是默认依赖

- V1 默认关闭全局热键。
- 用户在设置里可以主动开启。
- 开启时立即检测是否可注册。
- 如果冲突，只提示，不阻断。

#### 功能 7：最近一次会话恢复

- 记住最近一次截图、OCR 文本和回复结果。
- 用户关闭侧板后，仍可从贴边浮窗重新打开。
- 这样复制后不怕误关，也方便继续二次改写。

#### 功能 8：托盘与开机常驻

- 关闭窗口默认缩到托盘，不直接退出。
- 托盘菜单至少包含：
  - `显示浮窗`
  - `开始截图`
  - `打开上次结果`
  - `设置`
  - `退出`

### 7.3 Technology

#### 推荐模块结构

- `EdgeHandleWindow`
  - 贴边浮窗把手
- `ReplyPanelWindow`
  - 结果侧板
- `EditorDrawer`
  - OCR 编辑和场景切换区
- `CaptureOverlay`
  - 全屏截图遮罩
- `CaptureService`
  - 多显示器截图、截图数据输出
- `ClipboardImageService`
  - 从剪贴板读取图片
- `OCRService`
  - 本地 PaddleOCR 或远程 OCR API
- `LLMService`
  - 文心 OpenAI 兼容接口调用
- `PipelineController`
  - 串联截图、OCR、生成和重试
- `HotkeyService`
  - 可选热键注册与状态回传
- `TrayService`
  - 系统托盘入口
- `SettingsStore`
  - 保存位置、吸附边、是否置顶、热键设置等
- `SessionStore`
  - 保存最近一次截图、文字、结果和状态

#### 技术原则

- OCR 和模型请求必须在后台线程执行，不能卡住 UI。
- 截图、OCR、生成要拆成可恢复的独立步骤。
- 主状态应由状态机驱动，不要靠散乱布尔值拼接。
- 热键模块失败只能回传状态，不能让应用启动失败。
- 浮窗和侧板要尽量减少焦点抢占，复制后要让用户容易回到聊天窗口。

#### 推荐状态机

- `idle`
- `capturing`
- `ocr_running`
- `generating`
- `result_ready`
- `editing`
- `error_recoverable`

状态要求：

- `error_recoverable` 不清空已有截图和文字。
- `result_ready` 关闭侧板后，状态仍允许“重新打开上次结果”。
- 再次截图时，系统要提醒“将覆盖当前结果”，但不要直接丢数据。

#### 数据流

1. 用户从贴边浮窗点击 `截图` 或 `贴图`。
2. 系统得到图片数据。
3. `OCRService` 提取文字。
4. 文字先进入 `SessionStore`，再触发 `LLMService`。
5. `LLMService` 返回结构化回复数组。
6. `ReplyPanelWindow` 展示结果，并提供复制、重写、换风格和重新截图。

#### 默认回复策略

为了减少前置选择，V1 不要求用户先多选风格。系统默认一次返回 3 条不同层级的回复：

- 稳妥版
- 自然版
- 加分版

用户如果想切换场景，再通过编辑抽屉选择：

- 默认
- 职场
- 安慰
- 拒绝
- 邀约

这样可以让主流程更短，同时保留可扩展空间。

### 7.4 Assumptions

- 用户更需要“马上给我几条能发的回复”，而不是“先给我一个复杂工作台”。
- 浮窗的主价值来自稳定入口，不来自显示很多按钮。
- 默认自动生成 3 条回复，比让用户先选风格更符合高频场景。
- 热键保留为可选项，比强行依赖它更稳妥。
- 最近一次结果缓存，比完整历史列表更适合放进 V1。

## 8. Release

### V1：贴边浮窗助手

预计 1 到 2 周。

范围：

- 贴边浮窗把手
- `截图` 主入口
- `贴图` 次入口
- 自动 OCR + 自动生成
- 结果侧板
- 每条回复 `复制`
- `再来三条`、`更礼貌`、`更简短`
- 最近一次会话恢复
- 托盘基础入口
- 热键默认关闭，设置中可选开启

V1 不做：

- 完整历史面板
- 自定义提示词模板
- 多轮对话上下文
- 复杂动画
- 账号系统和同步

### V1.5：恢复和连续使用能力

预计再用 1 周左右。

范围：

- OCR 编辑抽屉
- 手动输入文字
- 场景模板切换
- 多显示器截图体验补齐
- 更好的失败提示和重试策略

### V2：更成熟的桌面助手

预计再用 2 周左右。

范围：

- 历史记录
- 自定义风格模板
- 最近常用回复策略
- 更完整的窗口自动收起规则
- 更好的焦点恢复和跨应用联动体验

## 附：建议实施顺序

1. 先把“贴边把手 + 截图遮罩 + 结果侧板”打通，确保不依赖热键也能完整使用。
2. 再把自动 OCR 和自动生成接成默认流水线，去掉多余的中间点击。
3. 然后补上最近一次会话恢复、贴图入口和托盘入口。
4. 最后再做 OCR 编辑抽屉、场景模板和可选热键设置。

## 附：本次改版的非目标

- 不在这一版里做 Web 主产品。
- 不在这一版里做账号体系。
- 不在这一版里做复杂插件机制。
- 不在这一版里把界面做成“大而全的工作台”。
